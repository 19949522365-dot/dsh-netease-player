# 网易云播放器 · dsh-netease-player

DSH 窗口底部常驻一条网易云播放条：搜歌、歌单、播放、歌词、扫码登录都在页面里，不用另开窗口、也不用切标签页。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [▣] 稻香 — 周杰伦 · 魔杰座        暂无歌词            ⏮ ⏸ ⏭  1:12 ━─ 3:43 ⌄ │
└──────────────────────────────────────────────────────────────────────────┘
```

底栏只有 **44px**，是一条「状态行」而不是播放器：左边 22px 封面 + `歌名 — 歌手`，
中间一条不发光的歌词线（两端渐隐，点一下开歌词页），右边是几乎隐形的运输键和细时间轴，
最底下 1px 线跟着播放进度走。悬停底栏时控制键会稍微亮一点。

点左边歌曲信息或最右的 `⌄` 展开面板。面板是 **600px 的双栏工具箱**：顶部一行封面 + 曲目 + 音量 + 收起，
下面一行六个页签，正文左边常驻歌词、右边是当前页签的内容，底部一条搜索框 —— 翻队列的时候歌词也还在。
「外观」「账号」这类设置页会自动切成单栏（歌词栏让位，别把卡片和二维码挤扁）。

| 页签 | 干什么 |
| --- | --- |
| 搜歌 | 搜歌名 / 歌手 / 专辑；底部搜索框右边可切「网易云 / B站」两个源，点一条就放，`+` 加进队列 |
| 队列 | 当前播放列表，点行切歌，垃圾桶移除 |
| 歌单 | 登录后读自己的歌单：点进去看曲目，点行播放、`+` 入队，还能「全部加入队列」 |
| 歌词 | 把歌词铺满整个面板（平时它是左栏那条） |
| 账号 | 扫码登录 / 粘贴 Cookie，看本地 API 服务在不在 |
| 外观 | 颜色、布局、密度、光晕、毛玻璃、动效（都存 localStorage） |

配色全部走 DSH 主题变量（`--dsw-alias-*` → `--np-*`），深浅两套都跟着系统主题走；
面板是一层玻璃 + 一根描边，没有第二层光，也没有海报区 —— 面板一打开就是能用里的东西。
正在播的那行左边一条 2px 强调色竖条 + 8% 色调底；页签是下划线式，一行六个不挤。
歌词跟唱只滚它自己那一小块，不会把面板滚走；点一句直接跳过去。

## 音源是怎么来的

- **登录后**：音源优先走本地服务的 `/song/url/v1`，会员曲目也能放；
- **本地服务没起来**：宿主还会直连 `music.163.com` 的公开 `player/url` 接口兜底（有 Cookie 才拿得到地址），
  所以服务冷启动那十几秒里点歌也不会哑火；
- 两种情况下，音频都是**宿主解析出真实地址再流式转发**（带 Referer、保留 Range），
  所以能拖进度条，也不会因为 CDN 的时效 token 过期而忽然播不动；
- `/play` 会逐个试候选音源，**回来的不是音频就直接扔掉换下一个**，不会再把 404 网页当 mp3 塞给 `<audio>`。

> 网易云按来源 IP 判地区：挂梯子 / 海外机房时，`/song/url` 会回 `code -460 检测到您的网络环境存在风险`。
> 需要时在 `POST /config` 里传 `realIP`（你的国内出口 IP），或设环境变量 `DSH_NETEASE_REAL_IP`。
> 插件本身不内置任何 IP。
>
> `music.163.com/song/media/outer/url?id=` 这个老外链网易已经废了（302 到 /404），
> 现在只是最后的兜底，别再指望它。

搜索/歌词/详情在本地 API 服务没起来时会自动改走 `music.163.com` 的公开接口兜底，
只有「登录」和「歌单」必须要有本地服务。

## B 站音源（可选，不用会员）

搜索框右边那个「B站」就是它。适合**网易云搜不到、或者歌要会员**的时候 —— B 站上华语歌的搬运覆盖率意外地高，
而且不用登录、不用大会员。

**它不是"照搬搜索结果"**：B 站搜出来一大堆鼓谱、翻唱、鬼畜、红石音乐、盘点视频，直接列给人看等于不能用。
所以宿主那边先过一层打分（`lib/bili.js` 的 `score()`）：

- 时长：2:30–6:30 加满分，太短（切片）太长（播客/合集）重罚
- 标题命中歌名 / 歌手加分，长的词权重更高
- 黑名单词重罚：鼓谱 / 教程 / 翻唱 / 鬼畜 / 合集 / 盘点 / reaction / 红石 / 光遇 …
- 专业搬运号加分：音乐私藏馆、JLRS-LeoFM、Hi-Res、4K 修复、官方 MV …
- 播放量取对数加成（不让爆款压死冷门但正确的版本），多 P 合集轻微减分

**技术链路**（纯 Node，无依赖）：`nav` 拿 wbi 密钥 → WBI 签名搜 `wbi/search/type` →
`view` 取 cid → `player/playurl?fnval=16` 取 dash 音频 → 带 Referer 代理转发。
浏览器拖进度条会发 Range，宿主原样透传并回 206；地址带时效签名，403/410 时丢掉缓存重解析一次。

**四个已知限制**：

1. **音质上限取决于视频**，一般 128–192k，比网易云 320k 差
2. **没有歌词**（视频没有 LRC），歌词页对 B 站歌是空的
3. **番剧 / 直播 / 充电专属**没有 dash 音频，会提示解析失败
4. **冷门歌看有没有人搬**，热门歌几乎必有

搜索接口：`GET /api/netease-player/search?source=bili&keywords=歌名 歌手`；
播放：`GET /api/netease-player/play?source=bili&id=BVxxxxxxxxxx`。

## 登录（可选）

登录要一个本地 NeteaseCloudMusicApi 服务（默认 `http://127.0.0.1:3020`）。
插件会自动认这两个位置：

1. `<DSH_HOME>/netease-service/server.js`
2. 当前工作目录下的 `netease-service/server.js`

找到之后，在「账号」页签点 **启动服务** 就行（冷启动大约 10 秒）。
没有这个服务时，扫码登录是不可用的，只能听普通音源。

登录过（`netease-player.json` 里有 Cookie）之后，**DSH 启动时会自动拉起一次**本地服务：
只要服务不在线就在后台拉，不阻塞启动，也不会重复拉；没登录则不会自动拉，省点内存。
自动拉起失败不影响手动点「启动服务」。

服务是冷启动，起来要十几秒。这段时间页面里 `serviceOnline` 还是 `false`，
所以歌单页开头会先显示「本地 API 服务还没起来」——属正常现象，**十几秒内会自动恢复**，
不需要刷页面；「重新检测」可以立刻重抓一次状态。

登录方式两种：

- **扫码**：账号页签 →「扫码登录」→ 网易云 App 扫一下；
- **Cookie**：浏览器打开 music.163.com 登录 → F12 → Network 随便点一个请求 →
  复制 Request Headers 里的整段 Cookie → 粘进输入框 →「保存 Cookie」。

Cookie 只存在本机 `<DSH_HOME>/netease-player.json`，接口不回显明文。

## 安装

### 从 GitHub 安装

仓库：<https://github.com/19949522365-dot/dsh-netease-player>

**一条命令（本机有 git 时）：**

```bash
npx @deepseek-ai/dsh plugin --profile web add github:19949522365-dot/dsh-netease-player
```

桌面端把 `web` 换成 `desktop`：

```bash
npx @deepseek-ai/dsh plugin --profile desktop add github:19949522365-dot/dsh-netease-player
```

**没有 git** 就用 GitHub 打的 tarball（实测 pnpm 能装）：

```bash
npx @deepseek-ai/dsh plugin --profile web add https://github.com/19949522365-dot/dsh-netease-player/archive/refs/heads/main.tar.gz
```

也可以下载 ZIP，在 DSH 的 **Plugins → Add plugin** 里选目录，或用 `link:<绝对路径>` 安装。

装完**重启 DSH**。要求 Node.js >= 22.12；DSH 版本太老（没有 `dsh.bundle` / `dsh.client` 支持）会装不上。

> 暂时没有发 npm；之后发 npm 或上架 DSH Market 时会补一句更短的安装命令。

要求 Node.js >= 22.12；DSH 版本太老（没有 `dsh.bundle` / `dsh.client` 支持）会装不上。

**本地 API 服务是可选的**：不装也能搜歌、放普通音源、看歌词（走 `music.163.com` 公开接口）；
要扫码登录、读自己的歌单、放会员曲目，才需要自己跑一个

然后在「账号」页签里配置/启动，或用 `POST /api/netease-player/config` 传 `apiBase` / `serviceDir`。

### 本地开发安装

源码在 `<DSH_HOME>/plugins/dsh-netease-player/`，profile 里以 junction 链接：

```
<DSH_HOME>\plugins\dsh-netease-player\                        ← 源码（改这里）
<DSH_HOME>\profiles\desktop\node_modules\dsh-netease-player   ← junction 指向上面的目录
<DSH_HOME>\profiles\desktop\package.json                      ← dependencies + dsh.profile.bundles
```

**改完要重启 DSH 才生效**：宿主端路由（`lib/index.js`）是跟着进程一起装配的，改了就重启；
只动了 `lib/client.js` 的话刷新一下页面就行（客户端 bundle 是页面加载时取的），
两边都想要稳，直接重启 DSH。

卸载：从 profile 的 `package.json` 里删掉 `dsh-netease-player` 两处，再删掉那个 junction。

## 合规说明

这个插件只是把你账号本来能播放的音源代理到网页里的 `<audio>`，不分发音频文件，也不破解会员。
请只在自己的账号和地区规则内使用，遵守网易云音乐、B 站的服务条款；公开分发带来的平台风险由使用者自担。

## HTTP 接口

浏览器半侧只走同源请求，不碰 RPC：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/netease-player/state` | 服务是否在线、是否登录、当前昵称（`?fresh=1` 跳过 1.5 秒的探测缓存） |
| GET | `/api/netease-player/search?keywords=&limit=` | 搜索（服务优先，公开接口兜底） |
| GET | `/api/netease-player/play?id=` | 音频流（支持 Range） |
| GET | `/api/netease-player/lyric?id=` | 逐行歌词 + 翻译 |
| POST | `/api/netease-player/cookie` | 保存 / 清空 Cookie（保存前先用 `/user/account` 校验） |
| POST | `/api/netease-player/config` | 改 `apiBase` / `serviceDir` / 音质 `level` / 风控用的 `realIP` |
| POST | `/api/netease-player/service/start` | 拉起本地 NeteaseCloudMusicApi |
| GET | `/api/netease-player/proxy?path=/xxx` | 通用透传（二维码登录、歌单走这里） |

歌单没加新路由，全部走 `/proxy` 透传：

| 透传的 path | 干什么 |
| --- | --- |
| `/user/playlist?uid=&limit=&offset=` | 我的歌单列表（`uid` 来自 `/state`，缺了再问 `/user/account`） |
| `/playlist/detail?id=` | 歌单详情，`trackIds` 拿来算总数 |
| `/playlist/track/all?id=&limit=&offset=` | 分页取完整曲目（`limit` 上限 1000，前端按 1000 一页翻，单张最多 10000 首） |

## 自检

```powershell
$node = "<DSH_HOME>\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
$p = "<DSH_HOME>\plugins\dsh-netease-player"

# 1) 宿主主链路：真去搜一首、拉一次歌词、请求一段音频
& $node "$p\tests\self-test.mjs" "$p\lib\index.js"

# 2) 宿主抗压：连续 Range 一致性 + 拖进度条时 abort 不泄漏连接
& $node "$p\tests\host-extra.mjs" "$p\lib\index.js"

# 3) 客户端渲染：假 React 把底栏和六个页签都真渲染一遍（不需要浏览器、不发请求）
& $node "$p\tests\client-smoke.mjs" "$p\lib\client.js"

# 4) 交互：带状态/副作用/重渲染的假 React，模拟点击底栏、页签、外观开关、静音、播放、Esc、点外面
& $node "$p\tests\interact.mjs" "$p\lib\client.js"

# 5) 快进：进度条在「dur 还没到 / 元数据没到 / 音源不可 seek」三种情况下都要有正确反应
& $node "$p\tests\seek-fix.mjs" "$p\lib\client.js"

# 6) 桌面端自定义协议：音源必须换成宿主的 http 地址，否则进度条拖不动
& $node "$p\tests\media-origin.mjs" "$p\lib\client.js"
```

`self-test` 会把 `apply()` 挂到假 ctx 上起临时 HTTP server，真的打网络，逐项打印 ok / FAIL。
`host-extra` 会在拿到音源后连发 8 次「拿到首包就 abort」的请求，模拟拖进度条，检查宿主不崩、
句柄不越攒越多。`client-smoke` 用假 React + 假 localStorage 把组件渲染成文本，专门抓改渲染代码后
留下的悬空引用（不需要装 React、不需要开浏览器）。
`interact` 更进一步：假 React 带**状态 + 副作用 + 重渲染**，能真的「点」——点底栏、切页签、
拖外观开关（布局/宽度/密度/光晕/颜色/歌词行/毛玻璃）、静音、播放/暂停、Esc、点面板外面、
切音源、拖音量、删队列里的歌、看默认页签，34 条断言。
`seek-fix` 专门盯进度条：拖动预览、松手只 seek 一次、指针捕获被抢、click 兜底、不可 seek 时的提示；
`media-origin` 盯桌面端音源地址（`dsh-app://` 下必须换成宿主 http 地址，普通浏览器保持相对路径）。

## 0.5.0 改了什么（首个公开发布版）

- 去掉 `private`，补 MIT `LICENSE`、`engines.node` 和 GitHub 安装说明；包名 `dsh-netease-player`。
- **去掉内置 realIP**：公开包不再带任何出口 IP；需要时由 `POST /config` 的 `realIP` 或
  环境变量 `DSH_NETEASE_REAL_IP` 提供。
- 本地 API 服务写成明确的**可选依赖**：不装也能搜歌 / 播放 / 看歌词，登录、歌单、会员曲目才需要它。
- 功能与 0.4.4 一致，只是发布元数据与文案整理。

## 0.4.1 改了什么（修桌面端进度条拖不动）

桌面端页面跑在 `dsh-app://` 自定义协议下。Chromium 的媒体管线对自定义协议的响应**不会发 Range**，
`<audio>.seekable` 恒为 `[0,0]` —— 进度条画面能拖、松手后 currentTime 被钉回原处，用户看到的就是
「快进没用」。`localStorage['np.seekdiag.v1']` 里留下的是 `seeked @0` + `seek-failed` + `seekable:[0,0]`。

- **宿主**：`/state` 多报一个 `mediaOrigin`（自己监听的 http 地址，如 `http://127.0.0.1:54154`）。
  取不到就回空串，不影响其它接口。
- **客户端**：自定义协议页面把 `<audio src>` 换成 `mediaOrigin + /api/netease-player/play?...`，
  走浏览器正常的 HTTP 栈（Range / 206 才生效）；普通浏览器页面（http/https）仍然用同源相对路径，
  行为不变。
- `/state` 还没回来之前**不挂 src**，避免先拿不可 seek 的地址起播、拿到地址后又从头重载一次；
  万一 `/state` 一直不回来，5 秒后放行（退回相对路径，至少能出声）。
- 旧宿主（没有 `mediaOrigin`）或 `/state` 失败时**退回相对路径**：歌能放，只是拖不动，不会整首放不出来。
- 新增 `tests/media-origin.mjs`：覆盖 `dsh-app://` / `http` / 旧宿主 / state 失败 / B 站源五种情况。

歌单没加新路由（走 `/proxy` 透传），所以自检里没有歌单用例；改完刷新页面，
分别试一下「未登录」「本地服务没启动」「登录后」三种状态下的「歌单」页签就行。

## 排障

- **底栏没出现**：宿主端要被装配，重启 DSH；确认 profile 的 `dsh.profile.bundles` 里有 `dsh-netease-player`。
- **能搜到但放不出声**：先看「账号」页签的本地服务状态；页面提示里会带上宿主记录的真实原因
  （`/state` 的 `lastPlayError`）。服务没起来就点「启动服务」；起来了还放不出，多半是这首真没版权。
  如果原因里写 `code -460` / 网络环境存在风险，就是风控，确认 `realIP` 没被清空（见上面「音源是怎么来的」）。
- **登录页一直转**：本地 API 服务没起来，点「启动服务」；还不行的看 `netease-service/service.log`。
- **自动拉起失败**：看 `netease-service/service.log`，也可以手动点一次「启动服务」（自动拉起只是启动时试一次，失败不会重试）。
- **刚启动头十几秒歌单页显示「服务还没起来」**：这是冷启动，不是坏了。页面在面板展开且「有 Cookie + 服务离线」时
  每 2 秒重抓一次 `/api/netease-player/state`，最多 15 次（约 30 秒），一拿到在线就停并自动读歌单；
  等不及就点提示里的「重新检测」立刻重抓，或去「账号」页签点「启动服务」。
- **二维码扫了没反应**：二维码两分钟过期，点「换个二维码」重来。
- **歌单页提示「登录后才能读歌单」**：歌单要登录 + 本地 API 服务在线，先去「账号」页签扫码 / 粘 Cookie；
  服务没起来就点「启动服务」。
- **歌单曲目一直转 / 读取失败**：上千首的长歌单第一次要按 1000 条一页翻，冷启动会慢十几秒（之后服务端有缓存）；
  失败就点「重试」，还不行看 `netease-service/service.log`。
- **桌面端进度条拖不动 / 松手弹回**：页面跑在 `dsh-app://` 下，自定义协议拿不到 Range，
  音源必须用宿主报的 `mediaOrigin`（本地 http 地址）。先看 `/api/netease-player/state` 里有没有这个字段：
  没有就是宿主还是旧版本，重启 DSH 或重载插件；有但页面还在弹回，看
  `localStorage['np.seekdiag.v1']` 里最近一条 `seek` 的 `seekable` 是不是 `[0,0]`。
- **播放偶尔卡顿 / 拖完进度条重新缓冲**：先确认宿主 `/play` 正常（`accept-ranges: bytes` + `content-length`，
  单个 Range 请求首字节约 70–300ms）。客户端只在松手时 seek 一次、切歌复用同一个 `<audio>` 不再重复 `load()/play()`；
  若仍卡，多半是宿主到网易云 CDN 那一段，看 `netease-service/service.log`。
